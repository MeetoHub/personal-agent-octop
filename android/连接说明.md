# Octop 手机端 · 连接说明

## 0. 网络现状（已实测）

| 项 | 值 | 说明 |
|---|---|---|
| NAS 内网 IP | `192.168.1.100` | 同一 WiFi 时用 |
| **NAS 节点小宝地址** | **`your-nas.example.com`** | **在外面也能用，实测 8089 返回 200** |
| Octop 端口 | `8089` | 监听 `0.0.0.0`，两条路都通 |
| 手机桥端口 | `8765` | App 自己起的，给 NAS 反调 |

NAS 侧的节点小宝网卡叫 `NodeBabyLink`，本机地址 `10.222.222.1`，
`your-nas.example.com` 是手机端访问它时用的地址。

**手机上打开节点小宝后，Octop 地址填 `http://your-nas.example.com:8089` 就能连，不用管 WiFi。**

## 1. 出包（这台 NAS 上没有 Android SDK，必须借机器）

### 方案 A：GitHub Actions（推荐，免费，不用装任何东西）

```bash
cd octop-mobile
git init && git add -A && git commit -m "init"
git remote add origin git@github.com:<你的账号>/octop-mobile.git
git push -u origin main
```

推上去后自动跑 `.github/workflows/build-apk.yml`，
到仓库 **Actions → Build APK → 最新运行 → Artifacts → octop-mobile-debug** 下 zip，
里面是 `app-debug.apk`，传手机安装。

### 方案 B：Android Studio（有 Windows/Mac 电脑时）

用 AS 打开 `octop-mobile` 目录，Sync 完点 Run。AS 会自己生成 wrapper 和 SDK。

> 第一版大概率有几处编译错误（这套代码一行都没编译过）。
> 把报错贴给我，我按真实错误修——比继续盲写有效得多。

## 2. 手机登录

1. 装 APK，打开
2. **先在手机上打开节点小宝**（重要，否则连不上）
3. 地址填 `http://your-nas.example.com:8089`
4. 用户名/密码 = 你在 Octop 网页端登录用的同一个账号
5. 连上后「任务」tab 显示的是你这个 agent 的真实会话列表

---

## 3. 授权

设置 → 手机能力 → 申请权限，依次给：联系人 / 短信 / 日历。

给完会显示「已授权」。这三项是运行时权限，只能手动点。

## 4. 让 NAS 上的 agent 能调手机（反方向）

这里是**反过来的**：不是手机连 NAS，而是 NAS 主动连手机的 8765。

### 4.1 手机上开手机桥

设置 → 手机桥 · 局域网 → 「开启」

点开后记下两样：

- **地址**：形如 `http://100.x.x.x:8765` 或 `http://192.168.x.x:8765`
  这一行显示的是 App 自己检测到的本机地址，**优先选 100 开头那个**（节点小宝给的，
  在外面也能通）。如果显示多个，用能通的那个。
- **令牌**：24 位字符串，点开可看全。

> 令牌不是可选项。同一个网段下别人也能扫到 8765，
> 没令牌等于把短信敞开给人看。App 会拒绝所有不带 token 的请求。

### 4.2 在 Octop 注册 MCP

Octop 网页端 → 专家 → 工具 → 自定义 MCP，新增：

```jsonc
{
  "octop-phone": {
    "command": "/usr/local/bin/python3.12",
    "args": ["/vol1/@appshare/octop-native/data/.octop/agents/lifebot/octop-mobile/nas/octop_phone_mcp.py"],
    "env": {
      "OCTOP_PHONE_URL":   "http://<手机在节点小宝里的IP>:8765",
      "OCTOP_PHONE_TOKEN": "手机设置页显示的那串令牌"
    }
  }
}
```

`OCTOP_PHONE_URL` 填**手机**的地址，不是 NAS 的。

### 4.3 先用手验证通不通

在 NAS 上执行（把 IP 和 token 换成手机的）：

```bash
curl "http://100.x.x.x:8765/health?token=<令牌>"
```

通了会返回：

```json
{"ok":true,"app":"octop-mobile","device":"...","android":34,
 "can_read_contacts":true,"can_read_sms":true,"can_read_calendar":true}
```

**这一步不通就别往下配**，先解决网络——大概率是手机在节点小宝里的 IP 不对，
或者节点小宝只做了单向映射。

### 4.4 验证 agent 能用

对话里说「手机上有哪些联系人」，agent 应该会调 `search_contacts`。

## 5. agent 能用的 6 个工具

| 工具 | 作用 |
|---|---|
| `phone_status` | 手机在不在线、三项权限给没给 |
| `search_contacts` | 按姓名查联系人 |
| `recent_sms` | 最近收发的短信 |
| `upcoming_calendar` | 未来 N 天日程 |
| `set_alarm` | 设闹钟（绝对时间或「N 分钟后」） |
| `phone_digest` | 联系人 + 短信 + 日程一次打包 |

---

## 6. 出门在外

已经解决：节点小宝组网，手机和 NAS 在同一个虚拟网里，
`your-nas.example.com` 走到哪都能用，不用开公网端口、不用配反向代理。

比直接暴露公网安全得多——现在是明文 http，token 走公网会裸奔。
