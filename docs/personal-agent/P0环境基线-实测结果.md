## 2. 三条对方案有实质影响的发现

### 发现 1：不是源码，是 wheel（但可改）

启动脚本 `/vol1/@appcenter/octop-native/bin/octop` 注释原文：
> 「包内仅含 Octop 核心 **whl** + 核心依赖 site-packages」

但——**目录属主是 `octop-native`，而服务正是以 `octop-native` 身份运行**：

```
drwxr-xr-x 1 octop-native AppUsers 2758  .../octop/infra/db/migrations
drwxr-xr-x 1 octop-native AppUsers  150  .../octop
```

**所以可以直接在 `site-packages` 里加文件、改文件，重启即生效。**
不需要打镜像，不需要 pip 重装。

**工期影响：0 天。原方案 12 天成立。**

> 唯一的注意事项：**升级 Octop 会覆盖这些改动。** 所以：
> - 改动必须记录成 patch 清单（见 §4）
> - 升级前用 `git diff` 或备份目录对比

### 发现 2：版本比本地源码低一版

| | NAS 实装 | 本地源码 | 差异 |
|---|---|---|---|
| octop | **1.0.3b6** | 1.0.3b7 | 低一版 |
| octop-harness | **1.0.10** | 要求 ≥1.0.11 | 低一版 |
| octop-memory | 1.0.4 | 要求 ≥1.0.5 | 低一版 |

**影响：** 本地读的源码是 b7，NAS 是 b6。两者迁移目录文件数都是 50、最新都是 025，
说明**迁移体系一致**。但具体代码可能有细微差异。

**处置：** 写代码前，先从 NAS 拉一份实际运行的 `octop/` 目录到本地对照，
以 NAS 上的为准（因为那才是要改的东西）。

### 发现 3：数据库 40MB 且正在活跃写入

```
-rw------- 1 octop-native octop-native  40M Nov 21 10:15 octop.db
-rw------- 1 octop-native octop-native 8.6M Nov 21 13:07 octop.db-wal   ← 3 分钟前还在写
```

**这意味着备份不能简单 `cp`。** SQLite 有 WAL 时，`cp` 主库文件会丢未合并数据。

**正确备份方式（三选一，按可靠性排序）：**

```bash
# 方案 A（最安全）：SQLite 在线备份 API
python3 -c "
import sqlite3
src = sqlite3.connect('/vol1/@appshare/octop-native/data/.octop/octop.db')
dst = sqlite3.connect('/vol1/@appshare/octop-native/data/.octop/octop.db.bak.20261121')
src.backup(dst)
dst.close(); src.close()
print('backup ok')
"

# 方案 B：先 checkpoint 再 cp
python3 -c "
import sqlite3
c = sqlite3.connect('/vol1/@appshare/octop-native/data/.octop/octop.db')
c.execute('PRAGMA wal_checkpoint(TRUNCATE)')
c.close()
"
cp octop.db octop.db.bak.$(date +%Y%m%d%H%M%S)

# 方案 C（最简单，但要停机）：停服务后 cp
# 服务停住后 WAL 会被 checkpoint，主库即完整
```

**推荐 A**：不停机、不丢数据、原子。

## 4. 必须建立的补丁清单（因为改的是 site-packages）

因为改的是 wheel 安装目录，升级会覆盖。所以从 P1 第一天起就要维护：

```
/vol1/@appshare/octop-native/data/.octop/patches/
├── MANIFEST.md              # 改了哪些文件、为什么
├── 026_tickets.sql          # 新增
├── 026_tickets.pg.sql       # 新增
├── routers_tickets.py       # 新增
├── app.py.diff              # 修改（加 1 行）
└── restore.sh               # 升级后自动重新打补丁
```

**`restore.sh` 是关键**——每次升级 Octop 后跑一次，把我们的改动重新贴回去。

```bash

# 2) 恢复

  > /vol1/@appshare/octop-native/data/.octop/octop.db
```

### 8.7 备份脚本（可复用）

把这段存成 `~/octop-backup.sh`，每次改前跑一次：

```bash
#!/bin/bash
BASE=/vol1/@appshare/octop-native/data/.octop
TS=$(date +%Y%m%d%H%M%S)
mkdir -p $BASE/backups
python3 -c "
import sqlite3
s = sqlite3.connect('$BASE/octop.db')
d = sqlite3.connect('$BASE/backups/octop.db.$TS')
with d: s.backup(d)
d.close(); s.close()
print('backup -> $BASE/backups/octop.db.$TS')
"
python3 -c "
import sqlite3
c = sqlite3.connect('$BASE/backups/octop.db.$TS')
print('integrity:', c.execute('PRAGMA integrity_check').fetchone()[0])
print('version:', c.execute('SELECT * FROM _schema_version').fetchone()[0])
print('agents:', c.execute('SELECT count(*) FROM agents').fetchone()[0])
print('thread_messages:', c.execute('SELECT count(*) FROM thread_messages').fetchone()[0])
"
```
