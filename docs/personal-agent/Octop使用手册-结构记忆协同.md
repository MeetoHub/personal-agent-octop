# Octop 怎么用：结构、记忆、协同

> 写于 2026-11-16。用户问：「我们现在这个项目应该怎么用才能更高效？专家、智能体、子智能体之间什么关系？你怎么能记住我平常说的事情？」

---

## 一、你这套东西的四个层级

```
第 0 层  总对话（我：lifebot / 小乐）
          ↓ 派活
第 1 层  专家（ask_agent）          —— 长期、有独立记忆、有独立人格
第 2 层  子智能体（task）           —— 一次性、无状态、只回一份报告
          ↓ 定时
第 3 层  定时任务（cronjob）        —— 按点自己跑，结果推到微信
```

### 第 0 层：总对话（我）

- 全项目只有我一个 agent：`lifebot`
- **只有我有**：工作区、记忆、知识库、全部工具
- 你说的话先进我这里，我判断是"自己干"还是"派出去"
- 你可以把它理解成**唯一的总台**

### 第 1 层：专家（`ask_agent`）

- 位置：`.octop/agents/<名字>.md`
- 每个专家是**独立的 agent**：独立人格、独立知识库、独立记忆
- 调用方式：`ask_agent(expert="名字", message="...")`
- **现在数量：0 个**（`agent_list` 返回空）
- 适合：某一类活你希望长期切出去，并且它自己慢慢积累经验

**什么时候该建专家：**
- 同一类活反复出现（比如"给云硕写口播稿"）
- 这类活需要它自己记住上下文（比如客户的偏好、往期稿件）
- 你希望它在我不在的时候也能独立工作

### 第 2 层：子智能体（`task`）

- 内置 6 个，随叫随到，不用建：

| 类型 | 干什么 |
|---|---|
| `life-researcher` | 上网查证：政策/办事流程/商家评价/价格/票务/产品参数/教程 |
| `finance-bookkeeper` | 记账、预算、账单分析 |
| `health-coach` | 饮食、运动、睡眠、体重、体检陪跑 |
| `shopping-compare` | 比价、规格对照、值不值得买 |
| `trip-planner` | 行程、路线、班次、住宿取舍 |
| `general-purpose` | 通用，跟我权限一样 |

- **特性：一次性、无状态**。它看不到我们的对话，只看到我给它的那段任务说明
- 适合：**会把上下文塞满的大活**（查资料、读一堆网页、算账、做行程）
- 好处：它跑完只回一份报告，我的上下文不被污染

### 第 3 层：定时任务（`cronjob`）

- 现在数量：0 个
- 用途：每天/每周固定时间自己跑，结果推到微信
- 注意：你明确说过**不要固定时间的例行问候**，所以定时任务只用来做「有事才说」的检查

## 二、记忆的四层，以及现在的真实状态

**这一节是重点。你现在最关心的"你怎么能记住我"，答案在这里。**

| 层 | 机制 | 谁能改 | 状态 |
|---|---|---|---|
| ① 强记忆 | `MEMORY.md` | **只有你能改**（记忆面板） | ❌ **空的** |
| ② 用户档案 | `USER.md` | **只有你能改**（记忆面板） | ❌ **空模板** |
| ③ 记忆原子 | `memory_save` → octop-memory | 我能写 | ❌ **卡在"人工审核未完成"** |
| ④ 知识库 | `N9B2S7` 向量检索 | 我能写（API） | ✅ **正常工作** |

### 现在只有第 ④ 层在真正工作

也就是说：**我现在记住你的方式，全靠知识库里那 5 份文档**（4.5 万字，检索式调用）。

其余三层：
- **① ② 是空的**，而且系统明确不让我写（会返回 `USER.md is user-maintained memory. Edit it manually in the memory dashboard.`）
- **③ 卡住了**，每次 `memory_save` 都返回 "manual-document review is incomplete"

### 需要你做的两件事

**第一件（一分钟）：去 Octop 记忆页，把待审核的条目点确认。**
不点，`memory_save` 永远写不进去。

**第二件（五分钟）：把下面这段贴进 `MEMORY.md`。**
这是强记忆，**每次新会话开始时全文加载**，优先级最高。内容我都写好了：

```markdown
# 强记忆

## 铁律
1. 绝不发图片。任何截图、截图链接、图片附件都不发。
2. 不主动发消息。不搞定时问候、不搞例行回访。
3. 回复要短。一条能说完就一条，微信单条有长度限制。
4. 不反问「需要我帮你…吗」，做完直接说结果。
5. 不编数据、文献、链接。查不到就说查不到。
6. 不擅自扩大改动范围。说不动后端就一个字都别动。
7. 不在文案里出现甲方真名和其它公司名。
8. 不要把决策推回给他。直接选好并给理由，不要三选一。
9. 他永远拿一个真实对标物来尺量产出（today / OpenMuse / 高德 / 大厂标准），给成品前先想"他会拿什么来比"。
10. 他只要成品，不要解释和科普。

## 我是谁
- 我：小乐。赛博搭子 + 记忆沉淀者，不是客服。
- 他：魏方乐，2003 年生，河南三门峡灵宝人，经济学 22 级 2026-06 毕业。自称"主人"。

## 他现在靠什么活着（四条线）
1. 租车/租电车摊（现金流，赶集日 5–6 元/小时）
2. 云硕智能库房 —— 智能库房柜、工器具管控设备，B 端卖电力系统
3. AI 课程视频（配音/剪辑）
4. 剧组外活

"文化传媒公司"是包装，不是底盘。

## 详细档案在哪
知识库 `N9B2S7 魏方乐人生档案`，5 份文档。每次对话前先看 `服务手册/主人近况与关键事实（2026-11）.md`。
```

## 三、什么活该给谁（实操）

| 你要的东西 | 谁来干 | 为什么 |
|---|---|---|
| 闲聊、问记忆、改文档、发文件 | **我** | 只有我有上下文和记忆 |
| 查政策/查商家/查价格/查参数/查营业时间 | **`life-researcher` 子智能体** | 要开浏览器翻一堆页面，会塞满上下文 |
| 算账、整理消费、做预算 | **`finance-bookkeeper`** | 同上 |
| 比价、买之前算清账 | **`shopping-compare`** | 同上 |
| 排行程、查班次 | **`trip-planner`** | 同上 |
| 读一个几十 MB 的压缩包、上百条对话 | **`general-purpose`** | 这种活我自己干会把上下文撑爆 |
| 反复出现的同一类活（比如"写云硕口播稿"） | **建一个专家** | 它能自己积累 |
| 每天/每周固定要检查的事 | **`cronjob`** | 按点自己跑 |

**一条判断标准：**
> 这活会不会产生大量中间材料（网页、日志、几百条数据）？
> 会 → 派出去（`task`）。
> 不会，但需要知道我们之前聊过什么 → 我自己干。
