## 明确的 bug（需要修）

文件：`app\src\main\java\com\octop\mobile\ui\components\ExpertAvatar.kt`

`LucideIcon` 的实现：

```kotlin
@Composable
fun LucideIcon(
    name: String?,
    tint: Color,
    modifier: Modifier = Modifier,
    sw: Float = 1.8f
) {
    val d = ExpertIconTable.pathFor(name)
    val path = remember(d) { PathParser().parsePathString(d).toPath() }
    Canvas(modifier) {
        val s = size.minDimension
        if (s <= 0f) return@Canvas
        val st = Stroke(width = s * (sw / 24f), cap = StrokeCap.Round, join = StrokeJoin.Round)
        scale(s / 24f, s / 24f) {
            drawPath(path, tint, style = st)
        }
    }
}
```

### 我的初步判断（不要盲信，你要自己看图确认）

`drawscope.scale(s / 24f, s / 24f)` 的 `scale()` 默认以 `center` 为 pivot，而不是左上角原点。
如果 pivot 是 center，24 单位坐标系缩放到 146px 时，图形会以 Canvas 中心为基准缩放，
导致超出/偏移。正确做法应该显式指定 `pivot = Offset.Zero`：

```kotlin
scale(scaleX = s / 24f, scaleY = s / 24f, pivot = Offset.Zero) { ... }
```

但格子1铺满整格的现象用 pivot 解释不通，所以**可能还有第二个问题**：
`ExpertIconTable` 里生成的多子路径字符串（比如 `"M3 3v16a2 2 0 0 0 2 2h16 M18 17V9"`）
用空格分隔多个 `M` 子路径，Compose 的 `PathParser` 对空格的容忍度、
以及 lucide 1.77 SVG 里的隐式数字简写（如 `m10.852 19.772-.383.924`）
可能没有被正确解析。建议逐个验证：

```kotlin
// 简单验证：取一个已知简单的图标，比如 "cloud"
val d = "M17.5 19H9a7 7 0 1 1 6.71-9h1.79a4.5 4.5 0 1 1 0 9Z"
```
